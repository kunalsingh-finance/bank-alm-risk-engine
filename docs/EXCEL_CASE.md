# Editable Excel interview case

`Bank_ALM_Case.xlsx` complements the audited Python report. It is an editable calculation case, with one active build, and a fixed import of the Python scenario summaries and aggregate event ledgers. It does not run Python or optimize funding from inside Excel.

On **Assumptions**, cell **E6** selects 1 = Base, 2 = Rising rates / deposit runoff, or 3 = Falling rates. The active row appears above each group of three blue case inputs. Editing a selected input recalculates the same **Earnings** and **Swap** schedules; **Summary** links their completed results. Unselected case inputs do not affect the active result. Blank required inputs produce `n.a.`; an explicit zero remains a valid assumption.

The editable case covers a parallel rate shock, deposit beta and repricing lag, deposit runoff, fixed-rate initial prefunding, payer-swap notional, operating expense and noncash credit loss. The original public dollar balances and curve observations are on **Sources** and remain fixed. Blue cells are editable research inputs, black cells calculate within a sheet, and green cells link across sheets. Shared inputs in E61:E74 feed one locally validated **Model input** column G; invalid values become `n.a.` and propagate to the relevant calculation. Fractions for loan mix, funding shock beta, initial margin and cash floor must be between zero and one. Operating expense, deposit rate floor and transaction fee must be nonnegative. Signed coupon rates and spreads remain permitted. Driver groups constrain fractional drivers to zero–one and reset lags to whole months zero–12. Source and fixed-import tabs use tan or muted styling.

The swap schedule has 60 dated monthly ACT/365F coupons, a base-curve par fixed rate, and a locked first floating fixing. Subsequent floating coupons use the shocked Treasury proxy curve. Remaining values discount the original future coupons by `D(t) / D(u)`; the 12-month case pays the final modeled coupon, settles the remaining ex-coupon value and releases collateral. Posted initial and negative-value variation margin use free cash. Positive received variation margin is segregated and unavailable. The formula schedule uses end-of-month dates because the saved bank date is December 31. There are no business-day adjustments or principal exchanges, and this is not a SOFR market valuation.

The earnings schedule deliberately uses static opening loan and securities balances for interest. It applies deposit runoff pro rata **at month end**: deposit interest uses the opening deposit balance, and cash interest uses the previous free-cash close, before the current month's withdrawals. It pays modeled operating expenses in cash, and deducts noncash credit losses from earnings and a separate net-loan-book rollforward. Default operating expense and credit proxies use reported annual noninterest expense divided by year-end assets and reported annual net chargeoffs divided by year-end net loans. These are editable research assumptions, not forward accounting provision estimates. Credit losses do not consume free cash. The schedule excludes noninterest income, asset amortization, prepayments, replacement business, security sales, taxes and regulatory-capital calculations. Case earnings are therefore not a forecast of reported net income.

All obligations and required collateral are assumed settled in this case. There is no reactive borrowing or security sale to repair a cash shortage. A negative free-cash balance and the **outside funding needed to the cash floor** show the shortfall explicitly. The workbook does not label such a case a feasible bank policy. Full bank EVE, shaped shocks, encumbrance constraints and constrained policy selection remain in the fixed Python reference.

**Engine reference** retains every saved reference and candidate scenario summary, the full policy grid, objective and limits. **Engine ledgers** retains every aggregate opening event and monthly event from the primary `output/analysis.json`, including its saved scalar and structured fields. Structured arrays or objects present in that file are retained as JSON text. The per-band asset arrays are deliberately omitted from the primary JSON and workbook; the complete segmented paths remain in the external compressed `output/analysis_full.json.gz`. The fixed imports do not update when blue Excel inputs change. Their engine build time, exact primary-analysis hash, source dates, capture dates, URLs and source hashes are visible in the workbook.

To refresh the public model and the fixed imports, run the offline report build and release verification first, then run the workbook builder with the bundled Codex Node runtime:

```powershell
python -S scripts/build_report.py
python -S scripts/verify_release.py
& "$env:USERPROFILE/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe" scripts/build_workbook.mjs
python -S tests/check_workbook.py
```

The builder requires the latest successful run status, its matching manifest hash, unchanged input/implementation fingerprints and a hash-matched analysis. It rejects a failed, interrupted or stale build before writing a workbook. It performs representative change/recalculate/restore tests, checks blank and zero inputs, scans formula errors, renders every tab, and exports cached formula values. The read-only validation script opens the XLSX XML, verifies cached results and source hashes, independently reconstructs dated swap pricing and cash/loan-book rollforwards, and checks the complete fixed-import row counts and native chart bindings. The exported workbook is under `outputs/01a0fce5-927e-7883-9b51-671e6a527eaa/Bank_ALM_Case.xlsx`; supporting render and validation evidence is in the adjacent `workbook_previews` directory. The workbook uses the bundled Artifact Tool authoring runtime; Excel itself is not required to regenerate it. Recalculation checks in that runtime do not establish identical behavior in every Excel version.
